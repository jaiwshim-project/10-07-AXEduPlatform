AI 플랫폼 아키텍처 이해

🎯 학습 목표
  • AI Native vs AI Enhanced 앱의 차이를 이해하고 프로젝트에 맞는 유형을 선택할 수 있다
  • RAG와 Fine-tuning의 장단점을 비교하고 적절한 전략을 수립할 수 있다
  • 멀티에이전트 아키텍처 패턴을 이해하고 설계에 적용할 수 있다
💡 핵심 개념
1. AI Native vs AI Enhanced
  • AI Native: AI가 핵심 기능 (예: Claude 기반 상담 플랫폼, AI 튜터)
  • AI Enhanced: 기존 기능에 AI 추가 (예: 검색 자동완성, 추천 시스템)
2. RAG vs Fine-tuning
  • RAG: 실시간 지식 검색 + 답변 생성 (빠른 업데이트, 낮은 비용)
  • Fine-tuning: 모델 학습 (특정 도메인 전문화, 높은 비용)
3. 멀티에이전트 패턴
  • Sequential: 순차 실행 (검증 → 분석 → 요약)
  • Parallel: 병렬 실행 (여러 소스 동시 검색)
  • Hierarchical: 계층 실행 (코디네이터 → 전문 에이전트)
🛠️ 실습 단계
  1. 3가지 AI 플랫폼 사례 분석 (30분)
    • ChatGPT, Notion AI, Claude Code 아키텍처 분해
    • 핵심 기술 스택 정리
  2. 아키텍처 비교표 작성 (20분)
    • AI Native vs AI Enhanced 비교
    • RAG vs Fine-tuning 비교
  3. 멀티에이전트 패턴 설계 (10분)
    • 본인 프로젝트에 맞는 패턴 선택
    • 에이전트 역할 정의

  • Must Have: 없으면 안 되는 기능
  • Should Have: 있으면 좋은 기능
  • Nice to Have: 나중에 추가할 기능

인증/권한 시스템

2시간
🎯 학습 목표
  • 회원가입/로그인 시스템을 구현할 수 있다
  • JWT 기반 인증과 세션 관리를 이해하고 구현할 수 있다
  • RBAC (Role-Based Access Control)을 설계하고 적용할 수 있다
💡 핵심 개념
1. 인증 (Authentication) vs 권한 (Authorization)
  • 인증: 사용자가 누구인지 확인 (로그인)
  • 권한: 사용자가 무엇을 할 수 있는지 확인 (역할)
2. JWT (JSON Web Token)
  • Header: 알고리즘 (HS256)
  • Payload: 사용자 정보 (userId, role)
  • Signature: 서명 (비밀키)
3. RBAC (Role-Based Access Control)
  • Admin: 모든 권한
  • User: 일반 사용자 권한
  • Guest: 읽기 전용
🛠️ 실습 단계
  1. 회원가입 API 구현 (30분)
    • 이메일/비밀번호 검증
    • 비밀번호 해싱 (bcrypt)
    • DB 저장 (Supabase)
  2. 로그인 API 구현 (30분)
    • 이메일/비밀번호 확인
    • JWT 토큰 발급
    • 세션 저장 (localStorage)
  3. 권한 검증 미들웨어 구현 (30분)
    • JWT 토큰 검증
    • Role 기반 접근 제어
  4. Frontend 통합 (30분)
    • 로그인 폼
    • 회원가입 폼
    • 세션 관리
📝 코드 예제
JWT 인증 미들웨어
import jwt from 'jsonwebtoken'; export function verifyToken(req, res, next) { const token = req.headers.authorization?.split(' ')[1]; if (!token) { return res.status(401).json({ error: 'No token' }); } try { const decoded = jwt.verify(token, process.env.JWT_SECRET); req.user = decoded; next(); } catch (err) { return res.status(403).json({ error: 'Invalid token' }); } } export function requireRole(role) { return (req, res, next) => { if (req.user.role !== role) { return res.status(403).json({ error: 'Forbidden' }); } next(); }; }

💡 핵심 개념
1. 요금제 설계
  • Free: 기본 기능, 제한된 사용량
  • Pro: 고급 기능, 확장된 사용량
  • Max: 모든 기능, 무제한 사용량
2. Stripe 연동 흐름
  • 1단계: Stripe Product/Price 생성
  • 2단계: Checkout Session 생성
  • 3단계: 결제 완료 후 Webhook 처리
  • 4단계: DB 업데이트 (tier, subscription_id)
3. Webhook 처리
  • checkout.session.completed: 첫 결제 완료
  • invoice.payment_succeeded: 구독 갱신
  • customer.subscription.deleted: 구독 취소
🛠️ 실습 단계
  1. Stripe 설정 (20분)

  2. Checkout API 구현 (40분)

Stripe Checkout API
import Stripe from 'stripe'; const stripe = new Stripe(process.env.STRIPE_SECRET_KEY); export default async function handler(req, res) { const { tier, userId } = req.body; const session = await stripe.checkout.sessions.create({ payment_method_types: ['card'], line_items: [{ price: process.env[`STRIPE_PRICE_${tier.toUpperCase()}`], quantity: 1, }], mode: 'subscription', success_url: `${process.env.SITE_URL}/success`, cancel_url: `${process.env.SITE_URL}/cancel`, metadata: { userId, tier }, }); res.json({ url: session.url }); }

    • 상태 다이어그램 작성

    • 에러 핸들링

class Orchestrator { async run(query) { // 1. Coordinator: 의도 파악 const intent = await this.coordinator.analyze(query); // 2. Retriever: 정보 검색 (병렬) const [docs, web] = await Promise.all([ this.retriever.searchDocs(query), this.retriever.searchWeb(query), ]); // 3. Analyzer: 데이터 분석 const analysis = await this.analyzer.process([...docs, ...web]); // 4. Generator: 답변 생성 const answer = await this.generator.create({ query, intent, analysis, }); return answer; } }
