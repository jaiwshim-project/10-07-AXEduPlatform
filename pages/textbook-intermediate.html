Module 1 (1시간)

클로드코드와 바이브코딩 이해

클로드코드의 역할, 바이브코딩 개념, 프론트엔드·백엔드·DB 관계, 파일 구조 이해

🎯 학습 목표

  • 클로드코드가 무엇이고 어떻게 작동하는지 이해한다
  • 바이브코딩(대화형 코딩)의 개념과 장점을 파악한다
  • 웹 플랫폼의 3층 구조 (프론트엔드·백엔드·DB)를 이해한다
  • 프로젝트 파일 구조를 읽고 해석할 수 있다

💡 핵심 개념

1. 클로드코드란?
Claude Code는 Anthropic의 AI 모델 Claude를 터미널에서 대화형으로 사용하여 코드를 작성하고 수정하는 CLI 도구입니다.
  • Read: 파일을 읽고 분석
  • Write/Edit: 파일을 생성하거나 수정
  • Bash: 터미널 명령 실행
  • Grep/Glob: 파일 검색
2. 바이브코딩 (Vibe Coding)
비개발자가 AI와 자연어 대화로 코드를 작성하는 방식. "로그인 폼을 만들어줘" → AI가 HTML + CSS + JS를 자동 생성.

기존 코딩: 문법 암기 → 라이브러리 학습 → 디버깅 → 배포
바이브코딩: 목적 설명 → AI가 코드 생성 → 결과 확인 → 수정 요청
3. 웹 플랫폼 3층 구조
프론트엔드 (Frontend): 사용자가 보는 화면 (HTML, CSS, JavaScript)
백엔드 (Backend): 데이터 처리 로직 (API, 서버)
데이터베이스 (Database): 데이터 저장소 (Supabase, PostgreSQL)
4. 프로젝트 파일 구조 예시
my-platform/
├── pages/           # 프론트엔드 (HTML 파일)
│   ├── index.html
│   ├── login.html
│   └── dashboard.html
├── css/             # 스타일
│   └── main.css
├── js/              # 프론트엔드 로직
│   └── app.js
├── api/             # 백엔드 (Vercel Serverless)
│   ├── login.js
│   └── register.js
└── README.md        # 프로젝트 설명

🛠️ 실습 단계

Step 1: 클로드코드 실행
터미널에서 claude-code 명령어를 입력하여 대화 시작
Step 2: 간단한 프로젝트 생성 요청
"간단한 웹사이트 구조를 만들어줘. index.html, style.css, script.js 포함"
Step 3: 파일 구조 확인
생성된 파일을 열어 HTML, CSS, JS가 어떻게 연결되는지 확인
Step 4: 수정 요청 연습
"배경색을 파란색으로 바꿔줘", "제목을 '안녕하세요'로 바꿔줘" 등 간단한 수정 요청

풀스택 플랫폼 구조 설계

🎯 학습 목표

  • 필요한 화면 목록을 작성한다

  • MVP (최소 기능 제품) 범위를 결정한다

💡 핵심 개념

1. 플랫폼 목적 정의
질문: 이 플랫폼은 무엇을 해결하는가?
예시: "교육 과정 수강생과 강사를 연결하고, 수강 이력을 관리하는 플랫폼"
2. 사용자 유형
  • 관리자: 모든 데이터 조회 및 수정
  • 강사: 자신의 강의 관리
  • 수강생: 수강 신청 및 이력 조회
3. 화면 구조 설계
  • 공개 화면: 홈, 과정 소개, 강사 소개
  • 인증 화면: 로그인, 회원가입
  • 대시보드: 수강생 대시보드, 강사 대시보드, 관리자 대시보드
4. 데이터베이스 테이블 설계
users: id, name, email, role, created_at
courses: id, title, description, instructor_id, duration
enrollments: id, user_id, course_id, status, enrolled_at
5. MVP 범위 결정
포함: 회원가입, 로그인, 과정 목록, 수강 신청
제외: 결제, 수료증 발급, 이메일 알림 (추후 구현)

🛠️ 실습 단계

Step 1: 플랫폼 목적 작성
클로드코드에 "교육 플랫폼의 목적을 정리해줘. 수강생과 강사를 연결하고 이력을 관리하는 기능"
Step 2: 사용자 유형 정의
"사용자 유형은 관리자, 강사, 수강생 3가지야. 각각의 권한을 정리해줘"
Step 3: 화면 목록 작성
"필요한 화면 목록을 작성해줘: 홈, 과정 소개, 로그인, 회원가입, 대시보드"
Step 4: DB 테이블 설계
"users, courses, enrollments 테이블 구조를 설계해줘. 각 필드명과 타입 포함"
Step 5: MVP 범위 문서화
"MVP에 포함할 기능과 제외할 기능을 정리해줘. README.md에 작성"
// 예시: MVP 기획서 (README.md) # 교육 플랫폼 MVP ## 목적 수강생과 강사를 연결하고 수강 이력을 관리하는 플랫폼 ## 사용자 유형 - 관리자: 모든 데이터 관리 - 강사: 자신의 강의 관리 - 수강생: 수강 신청 및 이력 조회 ## 화면 목록 1. 홈 (index.html) 2. 로그인 (login.html) 3. 회원가입 (register.html) 4. 대시보드 (dashboard.html) ## DB 테이블 - users (id, name, email, role) - courses (id, title, description, instructor_id) - enrollments (id, user_id, course_id, status) ## MVP 범위 포함: 회원가입, 로그인, 과정 목록, 수강 신청 제외: 결제, 수료증, 이메일 알림

// 예시: 로그인 API (api/login.js) import { createClient } from '@supabase/supabase-js'; export default async function handler(req, res) { if (req.method !== 'POST') { return res.status(405).json({ error: 'Method not allowed' }); } const { email, password } = req.body; const supabase = createClient( process.env.SUPABASE_URL, process.env.SUPABASE_ANON_KEY ); const { data, error } = await supabase.auth.signInWithPassword({ email, password }); if (error) { return res.status(401).json({ error: error.message }); } return res.status(200).json({ user: data.user }); }

예시: 커리큘럼 코치 에이전트 → 학습 목표를 입력받아 맞춤형 커리큘럼을 생성
2. 역할·입력·출력 구조
역할 (Role): "당신은 교육 커리큘럼 설계 전문가입니다"
입력 (Input): 학습 목표, 기간, 난이도
출력 (Output): 모듈별 커리큘럼, 학습 순서, 추천 자료

Step 2: 입력·출력 구조 설계
"입력: 학습 목표, 기간, 난이도. 출력: 모듈 목록, 학습 순서, 자료 링크"

"에이전트 프롬프트를 작성해줘. 역할, 입력 형식, 출력 형식 포함"
Step 4: 에이전트 UI 개발
"agent.html을 만들어줘. 입력 폼, 생성 버튼, 결과 표시 영역 포함"

"api/agent.js를 만들어줘. Claude API를 호출하여 커리큘럼 생성"
// 예시: 에이전트 프롬프트 템플릿 당신은 교육 커리큘럼 설계 전문가입니다. 입력: - 학습 목표: {goal} - 기간: {duration} - 난이도: {level} 출력: 1. 모듈 목록 (각 모듈의 제목, 시간, 내용) 2. 학습 순서 (권장 진행 순서) 3. 추천 자료 (참고 링크, 도서) 형식: Markdown 형식으로 작성. 모듈별로 구분.

Module 7 (2시간)

옵시디언 위키 개발

Markdown 구조, 내부 링크, 태그, MOC, Graph View, 위키 자동 생성

🎯 학습 목표

  • Obsidian의 개념과 장점을 이해한다
  • Markdown 문법을 익힌다
  • 내부 링크와 태그를 사용한다
  • MOC (Map of Content)를 작성한다
  • Graph View로 지식 구조를 시각화한다
  • 위키를 자동 생성하는 스킬을 만든다

💡 핵심 개념

1. Obsidian이란?
Markdown 기반 지식 관리 도구. 문서 간 링크로 연결된 네트워크 구조.
2. 내부 링크
[[문서 제목]] 형식으로 문서 간 연결
3. MOC (Map of Content)
주요 문서 목록을 정리한 인덱스 파일. 예: 00_INDEX.md
4. Graph View
문서 간 연결을 그래프로 시각화. 지식 구조를 한눈에 파악.

🛠️ 실습 단계

Step 1: Obsidian Vault 생성
프로젝트 폴더 내에 wiki/ 폴더 생성
Step 2: 주요 문서 작성
"00_INDEX.md, 프로젝트_개요.md, 기술_스택.md 작성해줘"
Step 3: 내부 링크 추가
"00_INDEX.md에서 다른 문서로 링크 추가"
Step 4: 위키 생성 스킬 개발
"프로젝트 파일을 분석하여 자동으로 위키 생성하는 스킬 만들어줘"
Step 5: Graph View 확인
Obsidian에서 Graph View로 문서 연결 구조 확인
# 예시: 00_INDEX.md # 교육 플랫폼 위키 ## 프로젝트 개요 - [[프로젝트 개요]] - [[기술 스택]] - [[폴더 구조]] ## 주요 기능 - [[로그인 시스템]] - [[수강 신청]] - [[대시보드]] ## 에이전트 & 스킬 - [[AI 커리큘럼 코치]] - [[페이지 생성 스킬]] - [[위키 생성 스킬]] ## 개발 가이드 - [[환경 설정]] - [[배포 가이드]] - [[트러블슈팅]] ## 태그 #프로젝트 #교육플랫폼 #Claude-Code
